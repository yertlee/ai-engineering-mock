# AI Engineering Mock

一个面向 AI 应用开发、Agent、RAG 和后训练岗位的模拟面试 Skill，尝试让 AI 的选题、追问和转题更接近真实技术面试的节奏。

> 当前是初版。我还没有亲自用它完成一场模拟面试，实际效果有待验证。后续会根据自己的使用体验继续调整和升级。

## 为什么做这个 Skill

这个 Skill 算是我对 AI mock 面试的一些想法。

找实习的时候，很多同学会让 AI 帮忙模拟面试，我也不例外。我搜索并尝试了一些 Skill，比如 grilling。它根据回答继续追问的思路很好，但在我把它用于模拟面试时，经常遇到一个问题：模型会盯着简历中的某个点一直往下问，十几个问题过去了，可能还停留在一个项目的某个实现细节里。问题之间即使有局部的承接，也缺少整场面试层面的安排。

这种练习当然能挖出知识盲区，但有时收获会越来越少，时间和 token 却还在不断消耗。grilling 本身更适合把一个设计或想法讨论透，用来模拟一场完整的求职面试，还需要调整。

最近参加几场真实面试后，我有了一个更明显的感受：面试官往往会结合自己部门的业务，从简历里找对应的经历。他们会问很具体的工程细节，也会在不同项目、不同层次之间切换，用有限的问题了解候选人。

我希望保留有价值的追问，同时补上这部分选题和转题的判断：哪些地方值得展开，什么时候已经了解得差不多，下一步该去看另一项什么能力。

所以简单做了这个 Skill。希望每次 mock 都能更有效地利用时间，获得一些具体反馈，找到值得继续补的地方——虽然大家对自己哪里薄弱，可能本来也有点数，hh。

## 它尝试怎么做

- **先有部门背景，再选题。** 有 JD 就以 JD 为基础；信息不足或没有 JD 时，生成一个具体的模拟业务部门，从工作目标、困难和约束推导考察方向。
- **沿项目运行的关联处发现细节。** 从模块如何调用、数据怎样传递、状态由谁维护等位置找问题，而不是随机抽技术名词。
- **追问兼顾广度和层级。** 默认约 12–16 道实质问题，包含追问，覆盖多段经历。是否继续追问，取决于它还能不能提供重要的新信息。
- **结束后给出有依据的评价。** 使用四档尺度，结合实际回答说明掌握程度、优势和改进点；区分独立回答、提示后回答和未充分考察。

技术亮点可以来自一个具体设计、实际改动或学习收获。项目尚未上线时，也可以在真实的实现与验证范围内展开讨论。

## 使用方式

将仓库中的完整 Skill 目录放入所用客户端支持的技能目录，保留 `SKILL.md`、`agents/` 和 `references/` 的相对位置。具体安装和发现方式以客户端为准。

提供简历或项目介绍后，可以这样开始：

**有 JD：**

```text
使用 $ai-engineering-mock，根据我的简历和下面的 JD，进行一场 AI 应用开发实习面试。
约 15 道题，追问计入题数，一次问一个问题，结束后统一评价。
```

**没有 JD：**

```text
使用 $ai-engineering-mock，根据我的简历模拟一个具体的业务部门。
这次偏 Agent 应用开发，进行一场兼顾广度与层级的面试，结束后统一评价。
```

也可以指定 RAG、Agent 平台、客户应用或后训练等方向，并调整岗位级别和题数。

## 文件结构

```text
ai-engineering-mock/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── department-selection.md
    ├── evidence-scoring.md
    └── behavior-checks.md
```

- [SKILL.md](SKILL.md)：面试流程、追问与转题规则。
- [部门设定与选题](references/department-selection.md)：从业务问题推导能力判断的示例。
- [证据与评分](references/evidence-scoring.md)：评价尺度、回答证据和复盘方式。
- [行为核查案例](references/behavior-checks.md)：后续迭代时检查是否出现单点深挖、预设实现等问题。
- [界面元数据](agents/openai.yaml)：技能名称、简介和示例调用提示。

## 当前状态与后续计划

目前完成了规则编写和基础格式校验，尚未完成我自己的完整多轮试用。因此，不能把这里的设计目标当成已经验证的效果，也暂时没有节约时间或 token 的实测结论。

接下来会重点观察：不同部门背景能否带来真正不同的考察重点；模型是否仍会在某个细节上停留过久；最终评价能否对应实际回答，并给出有用的练习方向。

如果你也用了，欢迎通过 Issue 分享体验。尽量带上问题路径、你认为该转题的位置，以及实际发生了什么，方便一起调整。
