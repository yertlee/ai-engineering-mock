# 技能行为核查

仅在维护/评估技能时使用。检查选择、停止和证据归因，不能只验证输出是否含某个词；无需每次模拟读取本文件。

| 情境 | 应有行为 | 应避免的行为 |
|---|---|---|
| JD 只有 Agent 和 Python 等泛化要求 | 保留要求，明确补充模拟业务目标和困难 | 编造该公司实际业务或假装 JD 已提供 |
| 改换为商品内容生产部门，仍使用同一份简历 | 从事实约束、人工修改、开放式质量等推导能力并找经历证据 | 只改部门名，照旧必考 SSE、DI、AST |
| 回答已说清 SQL AST 校验，一个子话题已连续三问 | 记录掌握程度，检查覆盖并默认转题 | 换 AST 节点名称，继续问十几题 |
| 只说 FastAPI，没有提到数据库或 Depends | 找真实服务关联，必要时先确认用法 | 假定数据库 Session 注入是唯一正确方案 |
| 候选人用显式传参代替 DI，并能说明边界 | 评价实际方案及取舍 | 因未使用预设框架机制扣分 |
| 候选人明确未负责接口鉴权 | 记录职责，可明确提出设计假设或转题 | 把不会说明既有实现等同造假 |
| 项目没上线，能讲清具体设计和离线验证 | 在相应范围评价，单列未验证的生产条件 | 要求编造规模或直接低评全部工程能力 |
| 候选人每题都答清楚 | 获得正面证据后转向其他能力 | 持续加难直到答错 |
| 候选人早期卡壳，两次问法都无更多信息 | 记录缺口，查看其他经历 | 整场围绕最早弱点反复确认 |
| 剩余四题，尚未涉及第二经历 | 优先补足另一经历并收尾 | 延长原分支再声称题数不足 |
| 用户在正式模拟中问解法 | 按请求教学，记录提示，再继续 | 拒绝讲解或将提示后答案算独立掌握 |
| 依赖注入一题没答出，其他链路清楚 | 局部缺口，综合其他证据评价 | 将整项工程能力判最低 |
| 一个缺口被追问三次 | 一项缺口，多条佐证 | 逐题扣三次分 |
| 未考察学习迁移 | 标注未充分考察 | 自动填低分或据简历猜高分 |
| 模型评审与候选人对框架行为意见不同 | 核实版本/资料或暂缓结论 | 用不确定知识纠错并扣分 |
| 同一轮三个问题都依赖上一个未答事实 | 一次只问当前可回答的主要问题 | 把整条分支打包并附标准答案 |
| 问“测试集怎么选、怎么防泄漏”后候选人指出这是两题 | 立即选择一个问题，另一项留待回答后追问 | 要求候选人按顺序回答两题，或把异议算作回避 |
| 用户明确要求项目、工程基础、场景与算法，早期项目追问已占大半预算 | 检查剩余覆盖并及时转题，复盘列明未考内容 | 沿同一项目继续追到预算耗尽，仍称覆盖了用户要求 |
| 正式语音模拟结束，文字报告尚未呈现 | 先交付可回看的报告，再简短口头总结 | 一边生成报告一边宣称已经显示，或把整份报告口述一遍 |

格式校验不代表上述行为已经通过真实试跑。维护时区分静态一致性检查、人工场景推演与实际多轮模拟的结果。
