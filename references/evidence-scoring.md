# 证据与评分

## 评分对象与预期

评分对象是本场要确认的能力，不是标准答案关键词命中数。面试开始前根据岗位级别和部门任务固定五项维度的具体含义，标出重点。允许根据回答调整选题，但不能事后提高候选人弱项的权重。

| 公共维度 | 核心判断 |
|---|---|
| 问题与任务理解 | 是否理解要解决的问题、约束和完成条件 |
| 实现与链路理解 | 是否能说明实际接触的实现及组件、数据、执行步骤的关系 |
| 设计与处理问题 | 是否能解释选择，并面对变化或失败作出合理判断 |
| 验证与结论 | 验证方式是否合适，结论是否受到证据支持 |
| 学习与迁移 | 是否从经历中形成认识，并能合理用于新场景 |

同一维度按部门体现不同：后训练的验证可看实验与数据隔离，客户应用可看业务验收与实际执行，内容生成可看开放式质量与人工反馈。框架、产品和算法经验都可能提供证据。

## 四档尺度

| 等级 | 含义 |
|---|---|
| 1：存在明显缺口 | 已考察范围内有关键理解错误，或无法说明必要机制 |
| 2：部分掌握 | 能说明核心思路或局部实现，但重要关联仍需引导 |
| 3：达到本场岗位预期 | 能独立说明相关实现与判断，支持承担相应范围工作 |
| 4：表现突出 | 在达到预期基础上识别关键约束、解释取舍或提出有依据的改进 |
| 未充分考察 | 证据不足以评价，不是最低档或零分 |

按实习/初级范围解释档位。一个小而完整、经验证的方案可以获得高档，不要求上线规模或完整系统所有权。单题不能轻易代表整个维度：结合相关分支；只有一处证据时标注判断暂定或范围有限。

## 增量证据记录

每个分支结束留以下简短记录，不需要每轮重写整份简历或评分表。保留必要原话片段，避免多次摘要造成失真。

```text
题号/经历/层次：
考察目的：
回答证据：关键陈述或短引文；已确认事实与假设分开。
缺口/限制：知识缺口、关联未说明、表达未展开、未负责或未测。
提示情况：独立回答 / 澄清题意 / 提示后回答。
分支结束或继续的理由：还有何种新证据值得获得，或为何转向其他能力。
```

这是可用于复盘的工作记录，不是逐步思维过程。正式模式中不展示答案和细粒度评分提示，不自动持久化个人材料。结尾只针对必要部分回看原回答以避免摘要误判。

## 判断约束

- 同一缺口被多次追问不累计扣分；重复证据只影响判断可信程度。
- 澄清题意不等于给答案，解法提示或教学后的回答必须单独标记。
- 表达抽象时先给一次具体化机会，不直接推断不会；表达流畅也不等于实现掌握。
- 明确没负责不等于概念错误。可考察迁移设计，但不能把假设方案记录成实际经历。
- 只有“不了解某框架机制”的证据时，评价局部知识，不直接推出整个工程能力差。
- 候选人对同一问题给出不同于预设的合理实现，按目标、约束和效果判断，不按关键词扣分。
- 未上线可标为生产适应性未被证明；不是实现错误或虚假成果的证据。
- 对矛盾先允许澄清。无法核实就说明证据不足，不能据一次卡壳指控造假。
- 沟通成本可以单独描述，不能用口条好坏替代技术评价。
- 技术事实不确定时核实或暂缓结论，不以模型记忆强行纠错。

## 最终报告

简短交代部门、级别、重点和覆盖限制。随后给出：

1. 实际问题路径：概括问题，选择关键追问/转题说明缘由；不罗列未问过的预案。
2. 能力表：维度、等级、回答依据、缺口或判断限制。不要用缺乏校准的精确置信百分比。
3. 有证据的优势；最多三个优先改进点，每项说明来自哪道题、缺口性质以及一次具体练习建议。

范例评价：工具调用关系说明清楚，资源释放这一处未能展开；目前只观察到局部机制缺口，尚不足以评价其他服务的生命周期管理。

另一范例：未接触生产流量，但能说明演示环境里的事务边界和重复提交验证，因此受控写入在该范围内达到预期；生产容量尚未考察。

默认不输出总分、招聘通过概率或行业排名。用户要求总分时，先说明换算口径与覆盖程度；若计划评分，在下一场开始前固定权重。临时要求可使用明确说明的等权描述性换算，未测维度排除并报告分母与覆盖，不能填零或填满分。覆盖不足时只给已测部分结果，说明不宜作为整场总分。

跨场比较需同时说明部门、重点和题目不同，不能把等级差异全部归因于能力变化。

## 成本与缓存

稳定规则与增量证据记录可以减少重复分析。记录复用和平台提示缓存是不同机制；不承诺命中率、费用降低或在没有统计时声称缓存成功。不得为了压缩记录丢失关键原话、提示情况和未测标记。
